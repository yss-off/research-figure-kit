# 2026-09-13：品牌流程海报复盘与插件优化

## 结论

本次迭代的主要问题是信息层级与真实观看尺寸没有先稳定下来；后来又把每次文案微调都做成独立脚本和版本目录，增加了成本。并非换一个配色或取消方框就能解决。

最终用户接受了品牌 logo、浅色圆角流程区、三个横排价格结果及简短备注。随后群聊配文只解释备注并指向海报。这些是本次成果，不是所有未来海报的固定模板。

## 经验 → 已落实的改进

| 经验 | 新工作流中的处理 |
| --- | --- |
| 条件判断被改成平行卡片，用户仍觉得原流程更清楚 | 保留用户选定的表达形式；比较与判断分别选型，样式修改不擅自替换逻辑结构 |
| 大菱形太重，全去掉方框又太空 | 先检查分组、信息密度与层级；框、圆角、填色按语义使用，不固定“全有框/全无框” |
| 备注一度成为两个大型宣传区，抢走主流程注意力 | 主流程、结果、备注分角色；备注面积、字号和色彩退后，内容仍完整 |
| 手机缩略图字体明显偏小，仍曾被描述为清晰 | 按实际导出坐标宽度计算显示字号，结合真实预览；结构、视觉判断、用户接受分开记录 |
| 手动换行留下大片空白，后来又切断词语 | 指定实际字体测量宽度；保护型号和必要短语；文案/字号/宽度变化时重算换行 |
| logo 尺寸反复调整，品牌配色只停留在换颜色 | 检查相对字号、品牌原图比例与留白，保留资产完整性；参考样式落实到具体几何和层级 |
| 文案从“技术”改成“渠道”，动作从“重新开通”改成“订阅” | 将最新纠正同步到稳定节点与相应备注，区分办理动作、渠道和条件 |
| 官方状态、备用选择、等待方案不断澄清 | 用户说法不是独立核验事实；不自动增加恢复日期、价格承诺或连续服务保证；并列选项不画成必经步骤 |
| 一次次微调生成新的脚本，形成 16 版演变记录 | 常规修订复用规范源和稳定 ID，仅改受影响文字与几何；仅在需要比较时保存快照，不删除历史 |
| 用户有时只想讨论，最后只想配一段群消息 | 严格保留讨论/执行边界；配文不重述整张流程图，指出“具体流程见图”即可 |

## 工程落地

- 新增 `drawio-poster`，仅处理非学术、以判断流程为核心的品牌海报；复用 sibling drawio，不混入论文 overlay 或数据图。
- 新增 `poster_tools.py audit`：读取单页未压缩 Draw.io XML，按明确的导出源宽和显示宽计算字号；显式 primary/secondary IDs，未分类与未知字号不通过。
- 新增 `poster_tools.py wrap`：使用本机指定字体和 Pillow 测宽，保留原文及字体哈希；不拆开英文型号或显式保护短语，处理基本中文行首/行尾标点。无法放入的 token 报错，不暗自缩小字号。
- 插件工程版本推进到 `0.3.4`（Unreleased），新增 skill 版本 `0.1.0`；既有三个 skill 版本不变。
- 新增 4 个海报路由案例，并将新 smoke suite 纳入 `make test`。

审查阈值是可配置的经验值，不是 WCAG 字号要求，更不是美观分数。`clear` 只表示该工具负责的检查未发现问题。

## 上游缺陷：只记录，不在本工程绕过固定基线

仓库 AGENTS.md 要求 bundled drawio 的维护通过固定上游更新进行。本次没有修改它，也没有把以下补丁复制到新 overlay：

1. **XML 空白误报（本次已复现）**：`validateXml` 用完整字符串匹配 `<mxCell id="0"/>` 和 `<mxCell id="1" parent="0"/>`；合法等价的 ` />` 形式被误判缺少根节点。原生紧凑 XML 返回 valid=true，仅插入空格就返回 valid=false。
2. **字体基线/空行兼容（本次海报已有证据）**：插件 SVG 的 dominant-baseline 与当前 librsvg 输出不一致，曾出现标题上移与空行丢失；当前绘图产物使用过任务内导出适配。需针对 renderer 版本另行复现后在上游修复，不能宣称已修好。
3. **圆角语义与主题覆盖**：service 样式可覆盖 default.rounded；Draw.io arcSize 的语义与 SVG 把数值作为 rx 的近似存在差别。要验证最终导出，而非仅检查配置键。
4. **无文字连接点/label-fit 启发式误报**：空格占位节点及文字边距估算可能产生 warning。记录实际可见结果，不批量忽略或自动改成 PASS。
5. **任意品牌图片的规范输入缺口**：曾需要在导出后插入 logo 图片节点；新工作流要求保留原始资产、比例和来源，正式图片规范支持仍需上游实现，不把手工插入宣称为 DSL 已支持。

## 安装与发布边界

本次修改工程源码并生成可审阅插件包，不修改已安装缓存，也不提交、推送或发布。仓库明确要求单独授权安装运行副本；新能力在安装新包并启动新任务后才会生效，不能把源码完成说成当前会话已加载。
